# AI Asset Curator

This repository keeps one canonical copy of every AI asset and generates the
tool-specific discovery surface from it. This skill is the operating manual for
that system: where each asset lives, which tool discovers what natively, how to
make changes without creating drift, and how to audit when something looks off.

Read `.ai/constitution.md` and `AGENTS.md` first if you have not already; this
skill implements their asset rules, it does not replace them.

## Layout And Native Discovery

| Path | Role | Discovered natively by |
| --- | --- | --- |
| `.ai/constitution.md` | Repository-wide policy | Nobody (entry points redirect here) |
| `.ai/instructions/*.md` | Canonical domain/language guidance with portable `paths` metadata | Nobody (adapters deliver it) |
| `.ai/agents/*.agent.md` | Canonical agent roles/personas | Nobody (read on demand) |
| `.ai/prompts/*.prompt.md` | Canonical reusable workflows | Nobody (read on demand) |
| `.ai/collections/` | Curated asset bundles (`.md` + `.collection.yml`) | Nobody |
| `.ai/skills/INDEX.md` | Skill registry and precedence rules | Nobody |
| `.agents/skills/<name>/SKILL.md` | Canonical shared skill library | Codex |
| `.claude/skills/<name>/SKILL.md` | Generated wrappers + Claude-authored skills | Claude Code |
| `.claude/agents/<slug>.md` | Generated subagents (selected roles) | Claude Code |
| `.claude/commands/<slug>.md` | Generated slash commands (from prompts) | Claude Code |
| `.github/instructions/*.instructions.md` | Generated path-scoped instruction adapters | GitHub Copilot |
| `.claude/rules/*.md` | Generated path-scoped instruction adapters | Claude Code |
| Entry points: `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md` | Redirects to `.ai/` | Codex / Claude / Copilot |

Claude Code does not scan `.agents/skills/`, and Codex does not scan
`.claude/` or `.codex/skills/`. The bridge between them is
`sync_ai_assets.ps1` at the repository root.

## The Sync Script

`sync_ai_assets.ps1` (run with `pwsh` from the repository root) generates
native host surfaces from canonical sources:

- A `.github/instructions/<name>.instructions.md` adapter for every canonical
  instruction under `.ai/instructions/`. It translates portable `paths` to
  Copilot `applyTo` metadata and embeds the canonical body.
- A `.claude/rules/<name>.md` adapter for every canonical instruction. It emits
  Claude's native `paths` list and embeds the same canonical body.

- A `.claude/skills/<name>/` redirect wrapper for every `.agents/skills/`
  skill. It copies the canonical frontmatter, forces `name:` to the directory
  slug, and appends `Read` to any `allowed-tools` list so the wrapper can
  always read its canonical source.
- A `.claude/agents/<slug>.md` subagent for each entry in the `$AgentRoles`
  table at the top of the script.
- A `.claude/commands/<slug>.md` slash command for each `.ai/prompts/` file,
  skipped when a same-named skill already provides `/<name>` invocation.

Every generated file carries the marker comment
`Generated by sync_ai_assets.ps1`. The script is idempotent: it deletes
only marker-bearing files before regenerating, and it warns-and-skips instead
of overwriting anything hand-authored. Files without the marker are therefore
safe, and hand-editing a file *with* the marker is always wrong — the next
sync run silently discards that edit. Fix the canonical source instead.

Run the script after every add, rename, or removal of a canonical skill,
agent role, or prompt, then review `git status` to confirm the wrapper delta
matches the canonical change.

## Workflows

### Add or update a shared skill

1. Create or edit `.agents/skills/<name>/SKILL.md`. Keep `references/`,
   `scripts/`, `assets/`, and `agents/` inside the same skill directory.
2. Frontmatter: `name` must equal the directory slug (lowercase, hyphens,
   max 64 chars); `description` states what it does and when to trigger
   (max 1024 chars). Preserve `license` and attribution on imported skills.
3. Run `pwsh ./sync_ai_assets.ps1` so Claude Code gets the wrapper.
4. If the skill belongs to a collection, update the collection `.md` and
   `.collection.yml` together.

### Add a Claude-only skill

Claude-authored skills that should not enter the shared library go directly in
`.claude/skills/<name>/SKILL.md` with no marker comment. The sync script will
never touch them; if a shared skill with the same name appears later, the sync
run warns and keeps the hand-authored file, so resolve the name clash then.

### Which root a new skill belongs in

- Meant for every tool (the normal case): the running tool writes to its own
  root per policy — Codex to `.agents/skills/`, Claude to `.claude/skills/` —
  unless the user explicitly asks for cross-tool placement, in which case the
  canonical copy goes in `.agents/skills/` followed by a sync run.
- Never write skills into `.ai/skills/` (registry only) or `.codex/skills/`
  (not discovered).
- Global/user installation only when the user explicitly requests it.

### Add or change an agent role

1. Create or edit `.ai/agents/<name>.agent.md` (keep the `.agent.md` suffix)
   with `name` and `description` frontmatter. Tool and model lists in role
   frontmatter are Copilot-specific; other tools ignore them.
2. To make the role a spawnable Claude subagent, add an entry to the
   `$AgentRoles` table in `sync_ai_assets.ps1` with a delegation-oriented
   description ("Use to ..."), then re-run the script. Keep the promoted set
   small — every subagent description occupies Claude context in all sessions.
3. Update any collection that lists the role.

### Add or change a prompt

1. Create or edit `.ai/prompts/<name>.prompt.md` with a single-line
   `description` in the frontmatter.
2. Re-run the sync script. It creates `/name` for Claude unless a same-named
   skill exists; if you want the prompt invokable under a different name,
   rename the file — do not hand-write a command wrapper.

### Rename or remove any canonical asset

1. Use `git mv` / `git rm` on the canonical file or directory.
2. Search for references before finishing: collections, `INDEX.md` prose,
   entry-point docs, and other skills or prompts may link to the old path
   (`git grep <old-name>`).
3. Re-run the sync script; it removes the orphaned generated wrappers itself.
4. For agent roles, also remove the `$AgentRoles` entry if one exists.

### Instructions and collections

- Instructions live in `.ai/instructions/<topic>.md`. Keep their portable
  `paths` frontmatter accurate. The sync utility translates it into Copilot
  `applyTo` and Claude `paths` metadata. Never edit the generated files under
  `.github/instructions/` or `.claude/rules/`.
- A collection is always a pair: human-readable `.md` plus machine-readable
  `.collection.yml` in `.ai/collections/`. Change both or neither, and keep
  their `path:` entries pointing at real files.

## Audit For Drift

Run this pass when assets have churned, after merges that touch `.ai/`,
`.agents/`, or `.claude/`, or when a tool is not seeing an expected asset:

1. `pwsh ./sync_ai_assets.ps1` then `git status --short` — any delta means
   the wrappers were stale (or someone hand-edited a generated file; the edit
   is now gone, which is the intended outcome).
2. Broken references: `git grep` each recently renamed or removed asset name
   across `.ai/`, `AGENTS.md`, `CLAUDE.md`, `.github/`, and collections.
3. Naming: skill directories and frontmatter names match and are kebab-case;
   agent roles end in `.agent.md`; prompts end in `.prompt.md`.
4. Frontmatter: every canonical skill, role, and prompt has a `description`;
   skill descriptions fit in 1024 characters.
5. Duplicates: a name existing in both skill roots is fine only when the
   Claude copy bears the generation marker; anything else needs a deliberate
   resolution, never an implicit merge.
6. Scope: retire assets that fall outside the curated scope listed in
   `.ai/README.md` rather than letting the library grow unbounded.

Report audit findings before deleting anything you did not create in the same
session, and ask before committing — repository policy requires explicit
approval for commits.
